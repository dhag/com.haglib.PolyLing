# PolyLing 外部受け渡し計画（モデル・モーションを全部運ぶ）

最終更新：2026-10-31（全段完了。ComfyUI の実データでの送信は `PolyLing_残件.md` の 6 へ移した）／2026-10-26（段⑤ 完了。実データでの送信は未確認）／2026-10-26（段⑥ 完了。検査済み）／2026-10-26（段④ 完了）／2026-10-26（段③ 完了）／2026-10-26（作成。ComfyUI は後回し）

外のプログラム（Blender・ComfyUI・素の Python）と PolyLing の間で、モデルの全データとモーションをネット経由（同じ PC のリモートサーバ）で受け渡せるようにする。
位置と面だけを送る今の経路をやめ、受け渡しの単位を「モデル丸ごと」と「モーション丸ごと」にそろえる。
1 段＝1 会話。各段の終わりにこの表の「状況」を書き換える。

## 1. 今の状態（コードで確認した事実）

| 向き | 経路 | 運ぶもの | 場所 |
|---|---|---|---|
| PolyLing → 外 | 照会 `project_bundle` | プロジェクト全体（ProjectDTO の JSON）＋テクスチャ画像（`embeddedTextures`）。応答は Binary フレーム | `RemoteServerCore.cs` `ProcessProjectBundleQuery`・`TryBuildProjectJson` |
| PolyLing → 外 | push `hierarchyBundle` | 上と同じ。受け手はエディタ拡張だけ | `RemoteServerCore.cs` `SendHierarchyBundle`、`Editor/HierarchyIO/HierarchyRemoteExportWindow.cs` |
| PolyLing → 外 | `getRawData`・`sendMeshToClient`（`putMesh`） | 位置と面だけ | 契約 §3.6 |
| 外 → PolyLing | `addMeshFromArrays`・`setVertexPositions` | 位置と面だけ。UV は (0,0)、材質の番号は 0 | `PlayerCommandDispatcher.MeshArrays.cs` |
| 外 → PolyLing | バイナリ `MeshData` | メッシュ 1 つ分（位置・法線・UV・ウェイト・面の材質番号など）。材質の中身・ボーン・テクスチャは無い | `RemoteServerCore.cs` `ProcessBinaryMessage` |
| 外 → PolyLing | バイナリ `RawFile` | 受けてログを出すだけ | 同上 |
| 外 → PolyLing | **モデル丸ごと** | **受け口が無い** | — |
| 両方 | `loadMotionClipJson`・`queryMotionClipJson` | モーション丸ごと（`.plmotion.json` v4 の中身） | 契約 §3.7 |

- Python の通信部（`poly_ling_py/polyling_io/net/client.py`）は、応答が Binary フレームで来ると失敗にする（`_on_binary`）。このため `project_bundle` を Python から受け取れない。
- Blender ブリッジ（`polyling_io/blender/bridge.py`）は位置と面だけを送受信する。全データを運ぶのはファイル経由の入出力アドオン（`importer.py`・`exporter.py`、`.mfproj`・CSV）だけ。
- `ProjectDTO` はモーションを持たない（`ProjectDTO.cs` の「将来用：モーションリスト」はコメントのまま）。モーションは `.plmotion.json` で別に運ぶ。

## 2. 決めること（この計画の方針）

1. **モデルの受け渡しの形は ModelDTO の JSON 1 つ**。`.mfproj` の `models[]` の 1 要素と同じ形に、テクスチャ画像（`embeddedTextures`：ファイル名とバイト列）を添える。新しい形式は作らない。
   - オブジェクト（メッシュ・ボーン）・頂点（位置・UV・法線・ウェイト・ID）・面（頂点・UV・法線・材質の番号）・材質・表情・Humanoid・揺れもの・VRM の情報まで、`.mfproj` が持つものは全部運ぶ。
2. **モーションの形は今の `.plmotion.json` v4 のまま**（§3.7 の 2 つのコマンド）。
3. **本体は Binary フレームで運ぶ**（`project_bundle` と同じ。JSON の UTF-8 バイト列）。要求と結果の報告は今と同じ Text の封筒。
4. **位置と面だけの外部経路はやめる**。`getRawData` の外部での使い方・`sendMeshToClient`／`putMesh` は、モデルの経路に置き換えて削除する。`addMeshFromArrays`・`setVertexPositions` はコマンドとしては残す（シナリオ・MCP が使う）が、外部連携の契約からは外す。
5. 受け取ったモデルの足し方は、PolyLing の他の操作と同じくディスパッチャを通す（担当者判定・Undo・操作者の記録をそろえる。操作経路統一計画.md R-3）。
