## 4. S1 図形生成

### 4-1. 位置は絶対値で入れる

`RobotBuildRecipe` の `Origin` は**親から見た相対値**。
階層を張る前は親がいないので、**先祖をたどって足した絶対位置**を入れる。
`WorldOrigin(name)` が同じ計算をしている。

### 4-2. 胴と腕で設定が違う

**前の部位の設定が残る。** 実際に、腕のために `RotZ = 90` と
`回転をベイク` を入れたまま次を始め、**胴 3 つが 90 度回った状態で作られた。**

| | 胴（小判型） | 腕（六角柱） |
|---|---|---|
| `RotZ` | 0 | 90 |
| 回転をベイク | false | true |

胴に移るときは `TrsReset` を押して回転を 0 に戻し、ベイクも外す。
腕に移るときは両方を明示的に入れ直す。
**「前がどうだったか」に依存しない形で毎回入れる。**

### 4-3. 作ったら座標で検算する

`queryDrawableStats` の頂点数・面数は、**向きが違っても同じ値になる。**
数が合っていても正しいとは限らない。

`getRawData` で座標を取り、軸の割り当てを確かめる。

| 形 | 正しいときの軸 |
|---|---|
| 小判型のセンター | X が ±0.102、Y が 0〜0.1、Z が ±0.06 |
| 六角柱の左腕 | X が 0〜-0.15（長さ）、Y と Z が断面 |

X と Y が入れ替わっていれば 90 度回っている。

### 4-4. 1 応答の分け方（片側上半身の実測）

| 回 | 中身 |
|---|---|
| 1 回目 | 胴 3 つ（センター / 上半身 / 上半身2） |
| 2 回目 | 腕 3 つ（左腕 / 左ひじ / 左手首） |

### 4-5. 諸元（片側上半身・実測値）

寸法は `RobotBuildRecipe.cs` が正典。下は確認用の控え。

| 部位 | 形 | 主な諸元 | 絶対位置 |
|---|---|---|---|
| センター | 小判型 | 0.22 / 0.1 / 0.12、分割 3・3・1、上下蓋なし、ピボット下 | Y=0.90 |
| 上半身 | 小判型 | 0.2 / 0.18 / 0.11 | Y=1.09 |
| 上半身2 | 小判型 | 0.22 / 0.18 / 0.12、高さ分割 3、上蓋あり | Y=1.36 |
| 左腕 | 六角柱 | 半径 0.045、高さ 0.15、上下蓋なし | X=-0.1853、Y=1.52 |
| 左ひじ | 六角柱 | 半径 0.04、高さ 0.135 | X=-0.4253 |
| 左手首 | 六角柱 | 半径 0.045、高さ 0.095 | X=-0.6503 |

左手首の高さ 0.095 は、以前スライダー下限（0.1）で丸められていた。
下限を 0.01 へ下げて解決済み（`CylinderMeshGenerator.CylinderParams.HeightMin`）。
入れたあと `uiGetValue` で読み返して確かめること。

## 5. S4 仕切り（センター下部）

`HowTo` は「下の開口の前側の辺を 1 本、後ろ側の辺を 1 本選ぶ（左右の中央）」。
座標から計算する。

1. `getRawData` で頂点座標を取る
2. Y = 0 の頂点が下の開口
3. 前側（z > 0）・後側（z < 0）に分け、**それぞれ x の昇順に並べる**
4. 隣り合う 2 点で **x の符号が変わるところ**が、中央をまたぐ辺
   （長さ方向の分割数が奇数なので、中央にちょうど辺が来る）
5. `createEdgeBridge` に辺 2 本と中間分割 3 を渡す

**期待する結果**：穴が 2 → 3。上の開口 12 点、下が 9 点ずつ。

## 6. S2 階層

`reorderMeshes` を使う。

- `category` は `Drawable`
- `entryValues` は **masterIndex / 深さ / 親の masterIndex を 3 個ずつ**並べる
- `preserveWorldTransform=true` にすると、見た目の位置が変わらない

片側上半身の一直線の入れ子なら:

```
"0,0,-1, 1,1,0, 2,2,1, 3,3,2, 4,4,3, 5,5,4"
```

**確認のしかた**

`queryModelStructure` は階層を返さない。オブジェクト原点を読むコマンドも無い。UI から読む。

1. `selectMesh`（引数は `category` と **`indices`**）
2. `uiReveal` してから `meshList.transform.positionX` を `uiGetValue`

組む前は絶対値、組んだ後は**レシピの `Origin`（親からの相対値）**になっていれば正しい。
例：左手首は 組む前 -0.6503 → 組んだ後 -0.225。

## 7. 面削除（上半身2）

`HowTo` は「上面の中央の長方形 12 枚」「側面の高さ中段にある左右の丸い部分 各 3 枚」。

**段の判別**：面を構成する頂点の Y 値を見る。
側面は 3 段（0〜0.06 / 0.06〜0.12 / 0.12〜0.18）、上面は 0.18。

| 対象 | 条件 | 実測の面番号 |
|---|---|---|
| 上面の中央 | Y=0.18 かつ 重心の \|x\| ≤ 0.05（丸みは \|x\|>0.05） | 36〜47（12 枚） |
| 側面中段の右 | Y 0.06〜0.12 のうち重心の x が正で \|x\| が大きい順 3 枚 | 15,16,17 |
| 側面中段の左 | 同じく x が負 | 21,22,23 |

`deleteFaces`（引数名は **`faceIndices`**）で 18 枚削除。

**中段でなければならない。** 最下段を消すと下の開口と、最上段を消すと上面の穴とつながる。

**期待する結果**：面 60 → 42、穴 4 つ（14 / 8 / 8 / 12）。
上面 14（首用）・側面 8×2（腕用）・下の開口 12 が独立していること。

## 8. 穴点数合わせ

`matchHoleRingCount` は穴を**種頂点**（その穴の縁にある頂点 1 つ）で指す。
`queryHoles` は個数しか返さないので、種頂点は `getRawData` の座標から決める。

決め方の例（上半身2 の左側面の穴）:

1. 面削除で開いた穴の位置は分かっている（側面中段 = Y 0.06〜0.12）
2. その Y 帯にあり、丸み部分（\|x\| > 0.05）の頂点を集める → 8 点
3. そのうち 1 つを種頂点にする（どれでもよい）

**基準側は変わらず、対象側だけ**点数が増える。
胴（8 点）を基準、六角柱（6 点）を対象にすると、六角柱が 8 点になる。

検算は `queryHoles` を両方に呼び、対象側が基準と同じ点数になり、
基準側が変わっていないことを見る。

## 9. 穴つなぎ

### 9-1. 引数は `NewObject`

シナリオ（`.Bridge.cs`）が渡している値:

| 引数 | 値 |
|---|---|
| `addMode` | **`NewObject`** |
| `addTargetIndex` | **-1** |
| `name` | `Bridge_<親名>_<子名>` |
| `flipCorrespondence` / `flipFaces` | どちらも false（自動判定にまかせる） |
| `subdivisions` | `RobotBuildRecipe.BridgeSubdivisions`（実測 3） |

`AddToExisting` を選ぶと既存オブジェクトへ面が足され、**そのオブジェクトが壊れる。**
実際に上半身2 が消え、左腕の位置が狂い、最初からやり直しになった。

### 9-2. 穴の数は減らない

**減らないことを失敗と判断しない。**

ここでいう「穴ふさぎ」はジオメトリ上の穴を閉じることではなく、
**見かけ上の橋を架ける**こと。橋は独立した新規オブジェクトなので、元の縁は残る。

完成しているかは次で判断する。

- 橋の面が作られたか（`queryDrawableStats` の面数）
- 両側の縁の頂点が重なる位置にあるか
- その頂点どうしのボーンウェイトが同じか（→ 11 節のウェイト塗り）

### 9-3. 片側上半身で張る 3 本

| 橋 | A | B |
|---|---|---|
| `Bridge_上半身2_左腕` | 上半身2 の左側面（8 点） | 左腕の胴側（8 点） |
| `Bridge_左腕_左ひじ` | 左腕の外側（6 点） | 左ひじの胴側（6 点） |
| `Bridge_左ひじ_左手首` | 左ひじの外側（6 点） | 左手首の胴側（6 点） |

胴の上面 14 点は首用。片側上半身に首は無いのでつながない。

## 10. S9 スキンド変換

```
convertMeshFilterToSkinned（引数なし＝既定値。シナリオと同じ）
```

板の集まりが、ボーンとスキンドメッシュの構造になる。

**期待する結果**（片側上半身・橋 3 本込み）:

| 項目 | 前 | 後 |
|---|---|---|
| メッシュコンテキスト | 9 | 18 |
| ボーン | 0 | 9 |
| 描画オブジェクト | 9 | 9 |

`queryBoneSkin` で内訳も見る。ルート 1、最大深さ 5（階層と一致）、
Humanoid 割当 6、スキンド化 9、使われているボーン 9。

### 索引がずれる

変換でボーンが先頭に挿し込まれ、**描画オブジェクトが 0〜8 から 9〜17 へ移る。**
メッシュ名には `_skinned` が付く。

変換後は `getRawData`（scope=Model）で索引と名前を取り直すこと。

実測の対応（片側上半身）:

| masterIndex | 名前 |
|---|---|
| 9〜14 | 各部位の `_skinned` |
| 15 | `Bridge_左ひじ_左手首_skinned` |
| 16 | `Bridge_左腕_左ひじ_skinned` |
| 17 | `Bridge_上半身2_左腕_skinned` |

ボーンの masterIndex は 0〜8。名前は元のオブジェクト名をそのまま継ぐ。

## 11. ブリッジのウェイト塗り

スキンド変換の**後**に行う。ウェイトの相手はボーンなので、変換前にはできない。

### 11-1. 配分

A 端 1.0 から B 端 1.0 へ直線で配る。分割 3 なら 5 段階。

```
1.00:0.00 / 0.75:0.25 / 0.50:0.50 / 0.25:0.75 / 0.00:1.00
```

**端を 0.5 ずつにしない。** 本体側の面と食い違って関節が折れる。
端は本体と同じ 1.0 にして、中へ向かって渡す。

### 11-2. 輪の見分け方

頂点の並び順は使わない（生成順に依存する）。
A 側ボーンから B 側ボーンへ向かう軸へ射影し、その値でまとめる。
射影値は橋の実体で正規化するので、ボーン原点が端とずれていても影響しない。

ボーンの位置は `selectMesh`（category=Bone）→ `uiGetValue boneEditor.worldPosition` で読む。
**座標を返すコマンドは無い**（`getRawData` は描画オブジェクト専用）。

### 11-3. 輪が揃わない橋がある

まっすぐな橋（六角柱どうし）なら射影値は等間隔に並び、輪がきれいに 5 本出る。

しかし**肩は両端の穴の向きが 90 度違う**（胴の側面と腕の端）ので、
射影値が散らばって輪にまとまらない。実測で 28 個になった。

**これは異常ではない。** シナリオにも肩の特別扱いは無く、散らばったまま `1-t : t` を送る。
「輪が揃わない＝失敗」と判断しないこと。

手数を減らすなら **t を 0.25 刻みに量子化**して 5 段階へまとめる。
配分の値は同じで、端を 1.0 にする原則も保てる。
実測では肩が 28 輪 → 5 段階になり、56 コマンドが 10 コマンドで済んだ。

### 11-4. 塗る手順（1 段階につき 2 コマンド）

```
selectElements（masterIndices は橋 3 本すべて / vertexIndices / vertexMeshIndices
                ＋ edgePairs 等の必須引数を空文字で）
setSkinWeightNumeric（boneMasters="A,B,-1,-1" / weights="0.75,0.25,0,0"）
```

`masterIndices` に橋 1 本だけ渡すと**前の橋の選択が残る**（汎用手順書 3 節）。

### 11-5. 検算

`querySkinWeightSummary` を橋ごとに呼ぶ。

| 橋 | 頂点 | 塗り | 2 ボーン | 使用ボーン |
|---|---|---|---|---|
| 肩（40 頂点） | 40 | 40 | 34 | 2 |
| 腕（30 頂点） | 30 | 30 | 18 | 2 |
| ひじ（30 頂点） | 30 | 30 | 18 | 2 |

`weighted` が全頂点、`distinctBones` が 2、
`multiBone` が「端以外の頂点数」になっていればよい。
